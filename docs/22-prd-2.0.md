## 0. 一页纸摘要

**产品是什么:** 把本机 AI agent 活动养成一座零联网的像素庭院。
**2.0 要解决什么:** 1.x 证明了"庭院好看",2.0 要证明"庭院值得天天回来看"。
**产品方向五支柱:** 活的庭院 / Agent 领地 / 时间的仪式 / 可信的答案 / 无摩擦的开始。
**UI 方向三件事:** 视觉宪法成文、信息架构从"按钮堆积"重构为"三层模型"、
关键新界面(tray、解锁时刻、年轮、数据抽屉、年报卡)出规格。
**已拍板的三个决定(2026-07-07,见 §8):** 数据抽屉——合并;Agent 领地——
苗圃案;v1.4 双地基——tray 守望 + 年轮写盘同步开工。
**两轮对抗 review 已吸收(2026-07-07):** tray 文案回归庭院叙事、年轮
事实迁 core、I7 移出 v1.4 gate、I0 缩水政策前置、去重键按类型分定义、
体验测试补验收协议(§3.1)、`launch_at_login`/`prices.json` 补落点契约。

## 1. 我们在哪:1.x 的资产盘点与三个未解问题

### 1.1 已经拥有的(别重做)

| 资产 | 现状 | 2.0 里的角色 |
|---|---|---|
| 双渲染器(WALL / 2.5D) | 完成,footer 一键切换,localStorage 记忆 | 场景层地基 |
| 项目藤蔓 + 成长分档 | tokens → vine 长度/叶量,`size_level` 在 core | 一切"成长感"的原料 |
| 解锁物件(亭/樱/柳/灯/饰品/五亿猫) | 当前由前端 `unlockTier` 统一计算;v1.4 I3 迁入 core `summary.tiers` | 解锁时刻(P1)复用,但事实来源迁 core |
| `.is-new` 新物标记 + return diff | 已有"离开后回来"的差异检测 | 周报明信片(P3)的数据源 |
| Postcard 导出 | PNG 导出 + 桌面原生保存(已随 v1.1.0 验证发布) | 所有分享物的输出管道 |
| 花坛系统(opt-in) | `render-flowerbed.js`,settings 可开关 | Agent 领地(P2)的候选载体 |
| Tray + 系统菜单 | Top Token Projects 子菜单、Scan Now | 守望模式(P1)的骨架 |
| i18n en/zh 层 + retro HUD 视觉 | paper/ink 色板、Silkscreen/VT323 字体 | 视觉宪法(§5.1)的既成事实 |
| 隐私底座 | 零网络 CI gate、CSP、PRIVACY.md、只读源目录 | 品牌本体,不可回退 |

### 1.2 三个未解问题(2.0 的靶心)

**问题一:新鲜感衰减。** 庭院第一眼惊艳,第三天就不再打开。物件解锁是
"里程碑级"的(百万/千万/亿 token),两次解锁之间可能隔几周,期间庭院
几乎静止。缺"日尺度"的可感变化和"看一眼就走"的形态。

**问题二:数字入口混乱。** footer 已有 明信片 / Insight / Dashboard /
WALL / 设置 五个按钮。Insight 和 Dashboard 都是"看数字",分工说不清
(用户本人也问过"明信片有必要吗")。每加一个功能塞一个按钮的路线已到头。

**问题三:庭院没有记忆。** 庭院只呈现"现在的状态",不记得"你是怎么走到
今天的"。第一株藤是哪天发芽的?亭子哪天升的级?最疯狂的一周发生了什么?
这些是情感产品最值钱的存货,现在全部丢弃。

## 3. 北极星与三个体验测试

**北极星体验(不是指标):** *"不打开主窗口的一周里,你依然知道你的庭院
活着;打开的那一刻,它记得你所有的来路。"*

落成三个可执行的验收测试,任何 2.0 特性设计完都要过一遍:

1. **两秒一瞥测试。** 用户从 tray / 刚弹出的 toast 获得的信息,两秒内能
   说出"今天/昨天发生了什么"。做不到 → 信息层级错了。
2. **周一明信片测试。** 周一第一次打开,系统给出的周报卡片,用户愿意
   不加修饰直接发到群里。不愿意 → 卡片设计不够好,不是用户的错。
3. **陌生人安装测试。** P-B 从下载到"第一次为自己的庭院截图"≤ 3 分钟,
   全程无需读文档。超时 → 首跑体验(P5)有断点。

### 3.1 验收协议(把"感觉"变成可证伪)

每个版本的 gate 只跑与其北极星对应的那一项;通过/失败都归档到年轮
式的测试记录里(docs/,不新增工具)。

- **两秒一瞥(v1.4 gate):** 5 名测试者(≥3 名非作者),展示 tray
  菜单 + 最近一条解锁横幅各 2 秒,提问"今天/昨天庭院发生了什么?"
  **通过 = ≥4/5 说出至少一个正确事实**(灯状态 / 新生长 / 活跃项目名
  任一)。失败归类:信息缺失 / 层级错误 / 文案歧义 → 分别对应改
  数据、改排序、改文案。
- **周一明信片(v1.5 gate):** 5 名 beta 用户收到自己的上周卡。
  **通过 = ≥3/5 表示愿意"不加修饰直接转发",且 ≥1 人实际发出**
  (以截图/链接为证)。失败归类:数据不对 / 版式不好看 / 信息太
  隐私(第三类触发"卡片可选隐藏项目名"的需求)。
- **陌生人安装(随 P5 出货的版本 gate):** 3 名没见过产品的开发者,
  只给下载链接,计时到第一张自发截图。**通过 = 中位数 ≤3 分钟且
  全程零文档求助**。失败归类:安装警告卡壳(签名问题)/ 白屏等待
  (I9 进度缺失)/ 空状态不知所措(I8 文案问题)。

## 4. 产品方向:五大支柱

> 每个支柱按同一模板展开:**问题 → 方案 → 功能明细(故事/验收/文案/边界)
> → 明确不做**。优先级与版本映射统一放 §6。

### P1 活的庭院(The Living Garden)

**问题:** 庭院是"状态的快照",不是"活着的东西"。里程碑之间是漫长的静止。

**方案:** 三个互相咬合的机制——守望(tray 常驻)、解锁时刻(变化的
庆祝)、年轮(变化的记忆)。让"变化"被看见、被庆祝、被记住。

#### P1-1 守望模式(Tray Watch)

- **故事:** 作为 P-A,我不想为了"看一眼"专门打开一个窗口;菜单栏的
  小图标应该替我守着庭院。
- **规格:**
  - 开机自启(opt-in,settings 新增 `launch_at_login`,默认 off——
    尊重谨慎者);
  - tray 图标两态:灯笼亮(今日有活动)/ 灯笼灭(无),macOS 用
    template image 适配深浅菜单栏,Windows/Linux 用彩色 16px 像素图;
  - tray 菜单第一行为只读状态行,**说"发生了什么",不说数字**
    (garden over charts 在系统层同样生效):`🏮 灯已亮 · 2 处新生长`
    (灯 = core tiers 的 `lamp` 活值;**新生长 = 今日(UTC)年轮事件数**
    ——seen-set 住前端拿不到,rings 事件是系统层的等价物且已在盘上;
    灯亮但 0 事件时显示 `🏮 灯已亮 · 庭院平静生长`)。token 数
    降级到 Top Token Projects 子菜单的首行(`今日 3.2M`)——数字被
    召唤才出现;其下保留现有 Top Token Projects / Scan Now / Open;
  - 主窗口支持"关闭即最小化到 tray"(settings 可选,默认关闭到 Dock
    正常行为,不做流氓驻留)。
- **文案与 locale(2026-07 已拍板并实现):** tray 是唯一读不到
  `web/i18n.js` 的双语面(native 菜单先于 webview 存在),文案以
  `tr(en, zh)` 对的形式住在 `crates/tauri-app/src/tray.rs` 调用点;
  语言由系统 locale 决定(`sys-locale`,`zh*` → 中文)——webview 的
  `navigator.language` 同源,两层天然一致。**不加 settings.locale**
  (没有手动切语言的需求,YAGNI;将来要了再加是兼容性加字段)。
  文案对:glance `Lantern lit · {n} new growth` / `灯已亮 · {n} 处新生长`;
  静默生长 `Lantern lit · garden growing quietly` / `灯已亮 · 庭院平静生长`;
  quiet `Garden is quiet today` / `庭院今日安静`;
  tokens `Today {tokens}` / `今日 {tokens}`(子菜单首行,数字唯一落点)。
- **边界情况:** 午夜跨日使用 UTC day-key(当前见 `garden-tiers.js` 注释,
  I3 后由 core `summary.tiers` 提供)时状态行刷新;
  无数据新机器显示 `tray.quiet` 而不是 0 堆砌。
- **不做:** tray 图标动画(耗电+打扰)、badge 数字(违反平静原则)。

#### P1-2 解锁时刻(Unlock Moments)

- **故事:** 作为 P-A,亭子升级成 full 的那一刻我想*看见*它发生,
  而不是三天后偶然发现"咦好像变了"。
- **规格:**
  - 触发:本次 scan 后的 `summary.tiers` 与上次前端可见帧的 diff。
    年轮事实由 core 在 scan/summary 管道写盘;前端只负责把这个 diff
    庆祝出来,并复用 `.is-new` seen-set 做一次性视觉标记;
  - 表现:场景内一条像素横幅从庭院门口升起,如
    `🏮 石灯点亮了 — 今天的第一行代码`,4 秒后自行沉落;同一次扫描多个
    解锁则排队逐条,最多 3 条,其余合并为 `+2 处新变化`;
  - 点击横幅 → 镜头(scroll/高亮)聚焦到对应物件,物件做一次 2 帧
    "眨眼"动画;
  - `prefers-reduced-motion` / motion=off:横幅改为静态出现静态消失,
    物件不眨眼;
  - 同一解锁事实由 core 同步写入年轮(P1-3)。
- **验收:** 用 fixture 数据把 totalTokens 从 900K 改到 1.1M,重扫后
  必须出现 scroll 饰品解锁横幅,且年轮多一条记录。
- **不做:** 音效(默认无声,连开关都先不做——YAGNI)、全屏彩带、
  任何形式的连击/连胜计数。

#### P1-3 年轮(Rings)

- **故事:** 作为 P-A,我想翻看"这座庭院是怎么长起来的",像翻一本
  只属于我的自然观察笔记。
- **规格:**
  - 数据:本地 append-only 的 `rings.json`(cache 目录,带
    schema_version),事件类型:`first_seen_project` / `tier_up` /
    `trinket_unlocked` / `busiest_day_record` / `season_change`;
  - 入口:数据抽屉(§5.4-D)内一个 tab,不占 footer 新按钮;
  - 形态:垂直时间线,每条 = 像素图标 + 一句话 + 日期,按月分组,
    顶部一行汇总(`这座庭院 213 天了 · 41 个时刻`);
  - **反连胜设计(核心价值观):** 只累积、永不清零、没有"中断"概念。
    没有任何一条记录会因为你休假两周而变红。
- **文案示例:** `2026-03-14 · 第一株藤蔓发芽(project: demo-pay)`、
  `2026-05-02 · 亭子扩建为全尺寸`、`2026-06-30 · 最忙纪录:单日 41M`。
- **不做:** 可编辑/可删除单条(它是自然史不是待办)、导出为社交图
  (年轮是私人的,分享物走 P3)。
- **写盘契约(工程,2026-07-07 对抗 review 后修订):**
  - **事实归 core,庆祝归前端。** 年轮是长期产品记忆,不能由前端视觉
    代码充当持久事实的作者(否则视觉阈值一改,历史就被 UI 改写)。
    因此:tier 阈值表迁入 core(先例:`size_level`/`size_strength`
    已是 core 字段),`GardenSummary` 新增 `tiers` 块并 bump
    `SUMMARY_SCHEMA_VERSION`(6 → 7);rings 的推导与写盘发生在 core
    的 scan/summary 管道内;Tauri command 只是读 rings 的薄壳。前端
    `garden-tiers.js` 退役为"读 `summary.tiers` → 映射 sprite",
    过渡完成后删除(可替换性检验:删它只动一处)。解锁横幅(P1-2)
    仍是前端职责——diff 前后两帧 `summary.tiers` 决定"庆祝什么",
    但"什么是事实"只有 core 说了算。
  - 单文件 `~/.local-agent-garden/rings.json`,形如
    `{ schema_version: 1, snapshot: {...}, events: [...] }`。
    `snapshot` 是上次已知的完整 tier 状态(pavilion/cherry/…/trinkets
    /每 agent 首见),`events` 是 append-only 日志。**二者永远在同一次
    原子写里更新**(临时文件 + rename),不存在"事件写了、快照没写"
    的中间态——这是防重复的第一道闸。事件检测 = 本次推导出的 tiers
    vs `snapshot` 的 diff。浏览器降级模式只读不写(demo 用样例)。
  - **去重键(第二道闸)按事件类型定义,与展示解耦:**
    - 跃迁类(`tier_up` / `trinket_unlocked` / `first_seen_project`
      / `season_change`):`{type}:{entity}:{to}:{utc_date}`,如
      `tier_up:pavilion:full:2026-07-07`。同日 small→mid→full 的
      多级跳是两条合法记录;数据回退后异日"二次达成"也是合法记录
      ——自然史想要的语义。
    - 纪录类(`busiest_day_record`):`{type}:{entity}:{utc_date}`,
      **键不含 `to`**;新值写进 payload。同日纪录再刷新 = 按键找到
      旧行、更新 payload,不追加新行。(旧稿"id 含 to + 先删后追加"
      自相矛盾——to 一变 id 就变,永远撞不上键;已废弃。)
    - 日期一律取检测时的 UTC 日(与数据层 day-key 一致),展示时
      本地化;追加前按键查重,存在即跳过(跃迁类)或更新(纪录类)。
  - **降级不记耻:** tier 回退(源日志被清理等)只更新 `snapshot`,
    不产生任何 event。庭院的记忆里没有"失去",只有"再次盛开"。
    注意:回退是否应该发生本身取决于 I0 的缩水政策(§8.4)——
    **I0 是本契约的前置**。

### P2 Agent 领地(Agent Plots)

**问题:** 多 agent 用户(Claude Code + Codex + Cowork)在庭院里看不出
"谁是谁"。而"我的 AI 们各自在我生活里占多大位置"恰是最有情感张力的
问题。这是 2.0 唯一的大视觉赌注。

**方案(推荐:苗圃案):** 沿庭院内墙根开辟 2-4 块像素苗圃(flowerbed
系统改造复用),每个活跃 adapter 认领一块。苗圃的花量/茂密度 =
该 agent 近 30 天 token 份额;hover 显示 `Claude Code · 68% · 2.1B`。
新 adapter 首次出现时,苗圃从"待开垦的土畦"渐变为初生花圃(本身就是
一个解锁时刻)。agent 断供 30 天,苗圃缓慢转为"休耕"(枯而不死——
平静原则,不惩罚)。

**备选(分区案,暂不推荐):** 把整个庭院按 agent 划分区块。视觉冲击
更强,但破坏现有构图、美术成本 3-5 倍、且 agent 份额剧烈波动时庭院
会"地震"。仅当苗圃案上线后用户强烈想要更强表达时再评估。

- **验收:** 双 adapter fixture 下,两块苗圃可见、hover 数据正确、
  停用一个 adapter 的 fixture 30 天后呈休耕态。
- **不做:** agent 之间的"对比/竞赛"文案(不做"Claude 碾压了 Codex"
  这种话,永远中性呈现份额)。

### P3 时间的仪式(Rituals of Time)

**问题:** 产品没有"时刻"。所有伟大的留存产品都有日历上的锚点。

#### P3-1 周报明信片(Weekly Recap)

- 周一首次打开(或 tray 菜单常驻入口),生成上周卡:本周 token 总量、
  最活跃项目 top3、庭院里新长出的东西(return diff 复用)、一句
  收束语(`上周,庭院多了一盏灯。`)。
- 复用 postcard 管道输出;卡片模板与年报卡同一套版式基因(§5.4-E)。
- 静默可关(settings:`weekly_recap: on/off`),关掉后 tray 菜单仍可
  手动生成——仪式感不等于强塞。
- **"上周"的边界契约(工程,防时区 bug 复发):** 触发与统计分离。
  **触发用本地时间**(周一是人的仪式:本地周一 00:00 之后的首次打开/
  tray 点击);**统计窗口用 UTC 日 key**(上一个 ISO 周的周一至周日
  七个 UTC 日期,直接匹配 `daily_tokens` 的 key,零换算、零重复、
  零缺漏)。已知代价:UTC+8 用户周日深夜的活动可能落进"下周"的卡,
  偏差最多一个晚上且逐周一致——在卡片角标注明日期区间
  (`06-29 – 07-05 · UTC`),诚实优于精确的假象。跨年周遵循 ISO 8601
  (第 1 周含首个周四),不自造历法。

#### P3-2 时令时刻(Seasonal Moments)

- 真实日历触发的场景变化,首批 4 个:樱花季(3-4 月,樱树满开+落瓣
  密度up)、锦鲤节(夏,池中锦鲤+1 条)、中秋(月亮 sprite 替换)、
  初雪(冬,雪覆盖变体已有季节系统承接)。
- 每个时令自动生成一张限定明信片模板(分享钩子)。
- **不做:** 节日弹窗祝福、限时任务("在樱花季达成 X"——那是游戏化)。

#### P3-3 年报(Year in Review)

- 12 月第一周解锁"年报"入口(数据抽屉内 + tray 菜单),生成 5 张卡:
  1. **封面卡:** 庭院全景 + `2026 · 你的数字庭院` + 总 token;
  2. **成长卡:** 年轮精选 5 时刻的竖版时间线;
  3. **巅峰卡:** 最忙一日/一周,当时在做的 top 项目;
  4. **伙伴卡:** agent 份额像素圆环(P2 数据);
  5. **结语卡:** 新年寄语 + 一粒像素种子(`明年,这里会长出什么?`)。
- 可整套导出长图或逐张导出;全部本地渲染,复用 postcard 管道。
- 参照系是 Spotify Wrapped 与 GitHub Skyline,但审美克制:纸感、墨色、
  无渐变彩虹。

### P4 可信的答案(Trustworthy Answers)

**问题:** 庭院引发好奇("这么大一座亭子到底花了多少钱?"),
产品必须接得住,否则用户去别处找答案就不回来了。

- **P4-1 成本估算:** 本地内置可编辑价格表(`prices.json`,随版本
  更新出厂默认,用户可改,**绝不联网取价**);Insight 每项目/每日
  增加估算成本行;显著标注"估算值,以账单为准"。多模型混用时按
  metadata 中的 model 字段分账,未知模型归"未定价"桶,不瞎猜。
  存储契约:出厂默认表作为应用资源随包分发;用户覆盖版落
  `~/.local-agent-garden/prices.json`(`schema_version: 1`),读写
  走薄 command(`load_prices` / `save_prices`),合并规则 = 用户版
  按模型名覆盖出厂版,未覆盖的条目随版本升级自动更新。
- **P4-2 Agent/模型拆分:** 数据抽屉新增"构成"视图:按 adapter、按
  model 两个维度的份额条(与 P2 苗圃同源数据,一处计算两处消费)。
- **P4-3 数据导出:** 每项目每日 tokens 导出 CSV/JSON(数据是用户的,
  让它可以离开)。桌面走原生保存对话框,浏览器降级模式走下载。
- **不做:** 预算报警/超支红字(平静原则;成本是"答案"不是"焦虑源")、
  任何形式的在线汇率/价格同步。

### P5 无摩擦的开始(Frictionless Start)

**问题:** 陌生人安装测试(§3-3)现在过不了:首跑是"扫描 → 哗一下
全出来",没有引导、没有惊喜编排;无数据用户看到的是空场景。

- **P5-1 生长首演:** 首次扫描完成后,庭院分层生长入场:地面 → 墙 →
  藤蔓(按项目大小依次抽芽)→ 建筑 → 生灵,全程 ~3.5s,可点击跳过;
  reduced-motion 直接呈现终态。仅首次,之后正常渲染。
  **首扫进度:** 大历史(数 GB JSONL)首扫可能数十秒,幕布期间消费
  `garden:scanning` 事件显示 `正在唤醒庭院… · claude-code`(adapter
  名随 payload 更新),避免陌生人安装测试死在白屏上。已核实:该事件
  watcher 已在发(`watcher.rs:95`)、前端已在听(`data-source.js:157`),
  缺的只是首跑幕布这个消费方;CLAUDE.md 事件表里"保留"的说法已过时,
  实现 I9 时顺手更正。
- **P5-2 空状态即邀请:** 无任何 agent 数据时,呈现荒地 + 一块像素木牌:
  `跑一次 Claude Code,回来看看这里` / `Run an agent once — then come
  back and watch this grow`,并列出当前支持的 agent 清单(检测到已安装
  但无数据的,点亮其名字)。
- **P5-3 浏览器演示模式:** `?demo=1` 加载内置样例 summary(现有
  `web/data/garden-summary.json` 通道),网站"在线试玩"直接用它——
  不装就能看到一座成熟庭院,装了才能看到*自己的*。
- **不做:** 分步向导弹窗(3 步 wizard 之类)、注册/问卷、
  "帮我们改进"复选框(没有遥测,没有这个框)。

## 5. UI 方向

> 原则先于像素:§5.1–5.2 把已经"事实存在"的视觉语言成文为宪法与 token,
> §5.3 重构信息架构,§5.4 给每个 2.0 新界面出规格,§5.5–5.7 是横切面
> (动效/无障碍/组件)。所有规格以现有代码为地基,标注复用点。

### 5.1 视觉宪法(8 条,违反即打回)

1. **像素完整性。** 所有 sprite 整数倍缩放,`image-rendering: pixelated`,
   任何情况下不出现半像素模糊边。新美术资产按显示尺寸 ≥1× 出图
   (2.5D v2 资产的教训:64px 拉大必糊)。
2. **纸与墨。** UI 面板 = 纸(`--paper`)上写墨(`--ink`);场景 = 昼夜
   天色。二者不混:纸面上不出现场景渐变,场景里不铺大块纸白。
3. **硬阴影,零圆角(retro HUD 层)。** `box-shadow: 2px 2px 0`(不模糊)、
   `border-radius: 0`、2px 实线描边——已是 postcard/settings pill 的
   既成风格,推广到一切新组件。
4. **文字永远有纸垫。** 场景之上不直接叠字;任何文字信息先落在纸片/
   横幅/木牌上,再进场景。(现有 hover 卡已遵守。)
5. **一屏一强调色。** 绿(`#6f9c3f`)是唯一的行动色;琥珀(`#d6a258`)
   只用于状态提示(stale/警示);不引入第三强调色。
6. **动效讲"发生",不讲"存在"。** 只有状态变化才动(解锁、生长、
   数据刷新);待机动画只属于生灵(猫/锦鲤/白鹭),UI 永不无故晃动。
7. **平静的层级。** 弹出物同一时刻至多一个(popover-group 已保证);
   通知不叠加、不闪烁、不带红点。
8. **双语等宽设计。** 任何文案框按 zh/en 中较长者留位;禁用依赖单一
   语言宽度的绝对定位。

### 5.2 设计 Token 清单(现值盘点 + 2.0 增量)

**色板(已存在于 `web/index.html` `:root`,成文即宪法):**

| Token | 值 | 用途 |
|---|---|---|
| `--paper` | `#f4ecd8` | 面板底、卡片底 |
| `--ink` | `#2c2316` | 纸上文字/描边/硬阴影 |
| `--paper-edge` | `#c9b790` | 纸面分隔线、滚动条 thumb(paper 主题) |
| 行动绿 | `#6f9c3f`(hover `#7daf48`) | 主按钮、rank、正向状态 |

### 5.3 信息架构 2.0:从"按钮堆积"到"三层模型"

**诊断:** footer 现状 = `明信片 · Insight · Dashboard · WALL · 设置`,
五钮并排。Insight(项目排行+搜索)与 Dashboard(KPI+图)本质都是
"数据视图",用户分不清;2.0 若再加 年轮/成本/年报,footer 将溢出。

**模型:** 全部 UI 归入四层,每层有唯一职责:

| 层 | 职责 | 载体 |
|---|---|---|
| **场景层** | 庭院本体,唯一主角 | 双渲染器画布 |
| **光环层** | 场景之上的瞬时信息 | hover 卡、解锁横幅、freshness 点 |
| **抽屉层** | 被召唤才出现的深度内容 | **数据抽屉**(合并后)、分享抽屉、设置 |
| **系统层** | 窗外的存在 | tray、系统菜单、原生对话框 |

**footer 重构(before → after):**

```
before:  [🖼 明信片] [📈 Insight] [📊 Dashboard]      [WALL] [⚙]
after:   [🖼 分享 ▾] [📈 数据]                         [WALL] [⚙]
```

- **数据抽屉** = Insight 与 Dashboard 合并为一个面板,顶部 TabBar:
  `概览`(原 Dashboard KPI)/ `项目`(原 Insight 排行+搜索,沿用
  sticky-head)/ `构成`(P4-2)/ `成本`(P4-1)/ `年轮`(P1-3)。
  URL/状态记住上次 tab。**§8.1 已拍板执行,但不进入 v1.4 gate。**
- **分享抽屉** = 明信片 + 周报卡 + 时令卡 + 年报(12 月点亮),
  一个入口四种产物,解决"明信片按钮存在感低"的老问题。
- WALL/2.5D 与 ⚙ 不变(视图开关与系统设置,语义独立)。
- 迁移策略:v1.4 先合数据抽屉(键位 `pg6-drawer-data`),
  分享抽屉随 P3-1 周报一起落(v1.5),不一次大爆炸。

### 5.5 动效原则

- **计时函数:** UI 移动一律 `steps(4~8)`(像素感的秘密——宁可跳格,
  不要丝滑);透明度渐变可用 linear。
- **时长阶:** 微反馈 120ms / 横幅升降 240ms / 抽屉开合 180ms /
  首跑全程 3500ms(唯一的长动画,一生一次)。
- **永不动的:** 数字(不做滚动计数)、面板内容(不做骨架屏闪烁)、
  tray 图标。
- **reduced-motion 映射表:** 生灵游走→定格姿态;横幅升降→淡入淡出;
  首跑→直出;锦鲤/落瓣→隐藏(现有行为,沿用)。

### 5.6 无障碍与双语

- 新组件 aria:横幅 `role=status aria-live=polite`(读屏播报解锁,
  不打断);数据抽屉 `role=dialog` + TabBar `role=tablist`;年轮
  `role=feed`。
- 键盘:全部新面板进 popover-group + Escape 关闭;tab 键序 = 视觉序;
  藤蔓 roving tabindex 机制不动。
- 对比度:`--ink on --paper` ≈ 12:1,达标;次级字 `#8a7656 on paper`
  ≈ 4.6:1,仅用于 hint 级文字(现状即如此,成文)。
- 双语:每个新 i18n key 必须 en/zh 同批提交(PR checklist 化);
  年报/周报卡上的日期用本地化格式(`fmtLocal` 已有)。

| 已有(复用) | 2.0 需新建 |
|---|---|
| 面板壳 `pg6-insight-panel` 系 + sticky-head 变体 | `TabBar`(数据抽屉) |
| `popover-group`(互斥)/ `pg6-popover-scroll`(滚动条) | `SceneBanner`(解锁横幅) |
| settings pill / toggle | `TimelineItem`(年轮行) |

## 8. 决策记录与开放问题

### 8.1–8.3 已拍板(2026-07-07,产品负责人确认)

   合并后年轮/成本/构成都有自然归宿。落地为 §6.1 的 I7——但定级

3. **§8.3 v1.4 双地基:tray 守望 + 年轮写盘同步开工。** tray 是

   否则年报缺一个版本的素材。落地为 I1–I4。

### 8.4 新开放问题(下一批,均不阻塞 v1.4 开工)

- **命名统一(阻塞 brew cask,建议 v1.2 签名前定)。** 现状分裂:
  README/CLAUDE.md 用 *Pixel Agent Garden*,而 `tauri.conf.json`
  productName、web `<title>`、i18n 均为 *Local Agent Garden*,CLI 叫
  `agent-garden`。cask token 与签名证书上的名字近乎不可改,必须先
  统一(倾向 *Pixel Agent Garden*——更可记、更可搜,"local" 的
  隐私语义由副标题承担;待确认)。
- **源日志轮转导致庭院缩水(工程答案已核实,只剩产品政策 → 升级为
  I0,v1.4 前置)。** 已查证:重扫是 REPLACE 语义——`cache.rs:71-89`
  fresh scan 后 `storage.rs:92` 整体覆盖 events.json,消失源的事件
  **必丢**,totals 下降 → 亭子降级,情感上等于"庭院被拆",且与年轮
  "永不缩水"直接冲突(两套真相)。政策二选一:缓存保留消失源的事件
  (庭院 = 累计史),或 tier 输入用持久化高水位(庭院永不缩水,
  Insight 仍显示真实现值)。推荐后者——展示与记忆分层,同 rings
  哲学一致;决策落 I0,rings(I3)以它为前提。
- **多机使用(已知边界,先说明后解决)。** 两台机器 = 两座庭院,
  年报会低估。v2.0 前仅在 FAQ 里诚实说明;远期逃生门是"导入另一台
  机器的 events 导出"(纯本地文件交换,不引入同步服务)。
- **tray 平台差异(I1/I2 实现时消化)。** macOS template image /
  Windows 彩色 ico / Linux appindicator 行为不一;验收以三平台
  doc 20 清单为准,允许 Linux 首版仅静态图标。

### 9.3 与工程合同的接缝(提醒未来的实现者)

- 年轮 `rings.json`(**core 写**,见 P1-3 契约)与价格表落
  `~/.local-agent-garden/`,带各自 `schema_version`(doc 11
  §Schema Versioning);seen-set 维持现状在前端 localStorage
  (`render-garden.js` 的 `pg6.seen.*`)——它只服务 `.is-new` 视觉
  标记,不是持久事实,不必迁移;
- 苗圃的 agent 份额在 core 聚合(`aggregate.rs` 按 source 维度),
  前端只消费——单向数据流不回头;
- tray 状态行数据走现有 `garden:updated` 事件,watcher 依然对内容无知;
- 所有新 UI 文件一件事一个文件,可整体删除(每个支柱都要能"一刀切除")。
